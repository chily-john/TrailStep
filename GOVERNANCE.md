# Governance

TrailStep uses a maintainer-led governance model.

The project welcomes outside contribution, but final decisions about roadmap, architecture, compatibility, and releases remain with the maintainer team. While the project is young, `@chily-john` is the project lead and release owner.

## Contributor path

Trust is earned gradually through consistent, constructive participation.

1. **Contributor** — anyone opening issues, discussions, docs fixes, tests, or pull requests.
2. **Trusted contributor** — a contributor with multiple useful merged PRs or sustained helpful issue participation.
3. **Triager** — can help label, reproduce, deduplicate, and organize issues without changing code.
4. **Collaborator** — can push branches and help maintain code, but still works through pull requests for protected branches.
5. **Maintainer** — can review and merge PRs in owned areas.
6. **Release owner** — can approve or perform package releases.

People should normally move one step at a time. Admin access should be rare.

## Adding collaborators

Before granting repository write access, look for:

- respectful communication
- alignment with project goals
- small, high-quality contributions
- tests/docs discipline
- patience with review and scope changes
- no pressure for broad access

Prefer starting with issue triage permissions before write permissions.

## Decision making

Maintainers try to explain decisions and seek input, especially for user-facing changes. Final calls may consider:

- project scope and long-term maintainability
- type safety and runtime durability
- backward compatibility
- release and support burden
- security and local machine safety
- whether the change fits TrailStep's workflow model

## Releases

Releases are controlled by maintainers. Contributors may propose changesets, but maintainers decide final version bumps and release timing.

## Conflict resolution

If discussion stalls, the project lead makes the final call. If a maintainer has a conflict of interest, another maintainer should review when available.
